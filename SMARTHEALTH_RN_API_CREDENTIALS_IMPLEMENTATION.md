## 📋 Executive Summary

This document outlines a **dual-layer security model** for the SmartHealth RN mobile app API integration that allows **Mediqzy Super Admin to manage and rotate API credentials independently** from user passwords.

### ✅ Why This Matters

```
Current Risk:
├─ 🟡 Mobile app uses user password (exposure risk)
├─ 🟡 No credential rotation without password reset
├─ 🟡 No audit trail of API-level access
└─ 🟡 Can't disable app access without affecting user account

New Solution:
├─ ✅ Separate API credentials (different from password)
├─ ✅ Super admin can rotate anytime
├─ ✅ Full audit trail of every API call
├─ ✅ Can revoke app access instantly
└─ ✅ Grace period for smooth transitions
```

## 🏗️ Architecture Overview

### Authentication Flow: 3-Layer Security

```
Layer 1: API Client Authentication (App Level)
    ↓
    Super Admin generates: client_id + client_secret
    App stores securely in keychain/secure storage
    Included in every request: Authorization: Basic <base64(client_id:client_secret)>
    
Layer 2: User Authentication (User Level)
    ↓
    User email + password sent in request body
    Verified against user account in database
    Generates JWT token for session
    
Layer 3: Device Authentication (Device Level)
    ↓
    deviceId + pushToken tracked
    FCM token registered for push notifications
    Device metadata stored for audit
```


## 🚀 Implementation Checklist

### Phase 1: Database Schema (1 hour)

**Create tables in PostgreSQL**:

```sql
-- API Credentials Table
CREATE TABLE api_credentials (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- Credential Metadata
  name VARCHAR(255) NOT NULL,
  description TEXT,
  integration_type VARCHAR(100),
  
  -- OAuth-like credentials
  client_id VARCHAR(100) UNIQUE NOT NULL,
  client_secret_hash VARCHAR(255) NOT NULL,
  client_secret_salt VARCHAR(32),
  
  -- Version Management
  version INTEGER DEFAULT 1,
  previous_version INTEGER,
  
  -- Scope of Access
  scopes JSONB DEFAULT '[]',
  
  -- Lifecycle Dates
  created_at TIMESTAMP DEFAULT NOW(),
  expires_at TIMESTAMP,
  last_rotated_at TIMESTAMP,
  rotation_required_at TIMESTAMP,
  
  -- Usage Tracking
  last_used_at TIMESTAMP,
  usage_count INTEGER DEFAULT 0,
  failed_attempts INTEGER DEFAULT 0,
  last_failed_at TIMESTAMP,
  
  -- Organizational Context
  organization_id UUID REFERENCES tenants(id),
  corporate_id UUID REFERENCES tenants(id),
  
  -- Status
  status VARCHAR(50) DEFAULT 'active',
  is_active BOOLEAN DEFAULT TRUE,
  
  -- Audit
  created_by UUID REFERENCES users(id),
  rotated_by UUID REFERENCES users(id),
  revoked_by UUID REFERENCES users(id),
  revoked_reason TEXT,
  revoked_at TIMESTAMP,
  
  metadata JSONB,
  updated_at TIMESTAMP DEFAULT NOW(),
  
  CONSTRAINT version_check CHECK (version > 0),
  INDEX idx_client_id (client_id),
  INDEX idx_organization_id (organization_id),
  INDEX idx_status (status)
);

-- Audit Log Table
CREATE TABLE api_credential_audit_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  credential_id UUID NOT NULL REFERENCES api_credentials(id) ON DELETE CASCADE,
  
  action VARCHAR(50),
  action_details JSONB,
  
  performed_by UUID REFERENCES users(id),
  performed_at TIMESTAMP DEFAULT NOW(),
  
  ip_address INET,
  user_agent TEXT,
  
  INDEX idx_credential_id (credential_id),
  INDEX idx_performed_at (performed_at)
);
```

### Phase 3: Mobile App Integration (3 hours)

**Update SmartHealth RN mobile app**:

```javascript
// 1. Store API Credentials (generated by super admin)
import * as SecureStore from 'expo-secure-store';

// Store securely on device
await SecureStore.setItemAsync('api_client_id', 'cred_smarthealth_xyz');
await SecureStore.setItemAsync('api_client_secret', 'generated_secret_here');

// 2. On every API request
const login = async (email, password) => {
  const clientId = await SecureStore.getItemAsync('api_client_id');
  const clientSecret = await SecureStore.getItemAsync('api_client_secret');
  
  const credentials = `${clientId}:${clientSecret}`;
  const base64Credentials = Buffer.from(credentials).toString('base64');
  
  const response = await fetch('https://api.mediczy.com/api/mobile/auth/api-credentials', {
    method: 'POST',
    headers: {
      'Authorization': `Basic ${base64Credentials}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      email,
      password,
      deviceId: device.id,
      pushToken: fcmToken
    })
  });
  
  return response.json();
};
```

## 🔒 Security Best Practices

### For Mediqzy Super Admin

| Practice | How to Implement |
|----------|-----------------|
| **Secure Communication** | Use encrypted email or secure vault to share credentials with development team |
| **Rotation Policy** | Set `rotation_required_in_days: 90` (standard enterprise policy) |
| **Monitoring** | Review usage dashboard weekly for unusual patterns |
| **Emergency Protocol** | Have procedure to revoke credentials within 5 minutes if breach detected |
| **Access Control** | Only super_admin role can generate/rotate/revoke credentials |

### For SmartHealth RN App

| Practice | How to Implement |
|----------|-----------------|
| **Secure Storage** | Store credentials in OS keychain (iOS) / KeyStore (Android) |
| **No Hardcoding** | Never hardcode credentials - download from secure server only once |
| **Encrypt in Transit** | Always use HTTPS for all API calls |
| **Refresh Tokens** | Use JWT refresh tokens for session management |
| **Update Immediately** | When super admin rotates, update app quickly within grace period |
| **Monitor Rotations** | Check for 401 errors - indicates credential change needed |

### Step 2: Add Middleware for Credential Validation

```javascript
// server/middleware/apiCredentials.middleware.js
const validateApiCredentials = async (req, res, next) => {
  const authHeader = req.headers.authorization;
  
  if (!authHeader?.startsWith('Basic ')) {
    return next(); // Optional - not all endpoints need it
  }
  
  const base64 = authHeader.slice(6);
  const [clientId, clientSecret] = Buffer.from(base64, 'base64').toString().split(':');
  
  // Verify credentials (done in route handler for this implementation)
  req.apiClient = { clientId, clientSecret };
  next();
};

export { validateApiCredentials };
```

## 📞 Support & Troubleshooting

| Issue | Solution |
|-------|----------|
| **401 Unauthorized** | Check API credentials are correctly encoded in Authorization header |
| **Credential Expired** | Super Admin must rotate credentials; app cannot use expired ones |
| **Grace Period Expired** | Old secret no longer works; must update to new secret immediately |
| **Multiple Failed Attempts** | Track in `failed_attempts` counter; might indicate security issue |
| **Lost Client Secret** | Cannot retrieve - must rotate to generate new one; design prevents retrieval as security feature |
