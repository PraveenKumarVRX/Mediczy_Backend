# CRM settings audit — 21 October 2026

Page: https://app.mediqzy.com/crm/settings. Audit only; application behavior and production configuration were not changed.

Authenticated production reads used the existing demo Business Head. Both profile and integration APIs returned 200; nine channels were returned, none with saved credentials. The real page incorrectly showed read-only access and zero save buttons. Controlled browser scenarios used the deployed JavaScript with intercepted synthetic profiles/settings and blocked every production mutation. Eighteen observations cover five roles, save/test/refresh/error cases and six desktop/mobile/theme combinations. Service scenarios executed the exact service source with an in-memory pool and synthetic encryption key. No real credentials, settings, calls, messages or consent records were changed. No browser runtime errors occurred.

## Findings

| ID | Severity | Confirmed issue | Required correction and acceptance |
|---|---|---|---|
| SET-01 | High | Browser capability map omits `communication:write`. Business Head, Marketing Head, telecaller and sales rep all receive read-only UI; only admin gets nine save controls. The server grants those roles write access. | Define a dedicated integration-configuration capability and mirror it across server/client. Verify allowed and denied roles using the same policy. |
| SET-02 | High | Credential PUT and Test routes use the ordinary message-sending capability. Server policy permits marketing, telecaller, conversion and sales rep to replace tenant-wide integration credentials through the API despite the read-only UI and its administrator/Marketing Head guidance. | Separate message sending from credential administration; enforce configuration permission on each route. Existing business-head override must be considered explicitly. No unauthorized live write was attempted. |
| SET-03 | High | Provider selection does not change input schema. Choosing SendGrid leaves SMTP host/username/password inputs and provides no API-key input. WhatsApp and calls likewise reuse one schema across different providers. | Render and validate an adapter-specific credential/configuration schema. Expose only supported providers; verify complete setup for every offered provider. |
| SET-04 | High | Partial credential rotation replaces the entire encrypted object. Saving Google Ads `clientSecret` alone removed an existing `refreshToken` in the isolated service reproduction, contradicting “Leave blank to keep saved secret”. | Merge explicitly changed fields into existing decrypted credentials atomically, validate the resulting bundle, and provide explicit per-field removal. Verify rotating either field retains its sibling and concurrent changes do not overwrite each other. |
| SET-05 | Medium | Test sends `{}` and tests saved credentials rather than visible edits. It reset an unsaved sender back to the saved sender. The service only decrypts credentials; synthetic invalid credentials pass without provider contact. Returned health message/score are not displayed. | Clearly distinguish storage verification from provider connectivity/delivery. Prevent testing an unsaved draft or explicitly save it first; retain draft values and display health failures. Do not imply verified delivery. |
| SET-06 | Medium | Refresh unmounts all cards and silently discards configuration and secret drafts. Both losses were reproduced. | Track dirty state; retain drafts or obtain an explicit discard choice. Test refresh and navigation with multiple edited cards. |
| SET-07 | Medium | An initial integrations 503 shows an error followed by nine “Not configured” cards with nine enabled save buttons for an admin. Unknown configuration is presented as empty configuration. | Show a failed-load state with retry; prohibit writes until the authoritative snapshot loads. Retain previously loaded data on refresh failures. |
| SET-08 | Medium | With a cached profile present, profile 503 is hidden. The cached profile remains visible and cached admin status enables editing. The API still authorizes writes independently; this is stale UI state, not a demonstrated authorization bypass. | Surface profile errors even with cached data; label stale data and keep privileged controls disabled until role refresh succeeds. |
| SET-09 | Medium | Sender and port inputs accept arbitrary text. The deployed browser submitted `not-an-email` and `not-a-port`; the isolated backend also accepted those values and an unsupported provider. Its only provider validation is nonempty/length. | Validate channel/provider combinations and typed required fields on the server, mirror helpful client validation, and identify field errors without losing input. |
| SET-10 | Medium | Save failure is visually rendered but has no alert/status/live-region announcement. Secret visibility controls measure 16×16 CSS pixels desktop and 14×14 mobile, with repetitive generic names across channels. | Announce asynchronous results, give controls channel/field-specific names and generous touch targets. Small size is an ergonomics observation, not a blanket WCAG failure claim. |
| SET-11 | Medium | Low-contrast text persists in both theme preferences. Measured examples: profile email 3.82:1, designation 2.40:1, faint placeholder minimum 1.95:1. | Adopt the coordinated CRM palette and verify enabled small text/placeholders at ≥4.5:1, excluding disabled controls and gradients from numerical claims. |
| SET-12 | Low | Desktop has the sidebar's Mediqzy text but no canonical logo. Mobile hides that sidebar and has neither Mediqzy identity nor logo in the settings workspace. Thirty-eight inputs form a long undifferentiated page. | Add canonical brand identity visible at phone widths; group/provider-filter fields and provide channel navigation. This is a product-consistency finding. |
| SET-13 | Medium | No disable, disconnect or clear-credentials action exists. Omitting credentials preserves the encrypted bundle; supplying a nonempty object replaces it. There is no supported explicit credential removal workflow. | Add authorized disable/disconnect and explicit removal with confirmation/audit evidence; verify disabled adapters cannot dispatch. |
| SET-14 | High | Saved tenant credentials are not consumed by the inspected delivery paths. The registry decrypts only inside its storage-test function. CRM email uses the shared transactional mail service, WhatsApp/SMS use process-level services/environment settings, and contact-center calling uses `cc_configs` plus approved server bindings. Saving Calls here does not configure Exotel or LiveKit calling. | Implement tenant-scoped adapter resolution for supported channels or label these records as inactive inventory and link to actual provisioning. Preserve tenant-bound telephony safeguards and LiveKit readiness separation. Verify the chosen tenant/provider is used in a controlled delivery test. |

Priority: **five High, eight Medium, one Low**. Address configuration authorization, credential preservation and actual adapter wiring before adding provider choices.
