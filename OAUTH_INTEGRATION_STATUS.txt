OAUTH ENDPOINTS (LIVE & TESTED)
================================================================================

1. GET /oauth/authorize
   Status: ✅ Working
   Purpose: User authorization & auth code generation
   Protection: authUser middleware (requires login)
   Response: 302 Redirect with auth code

2. POST /oauth/token
   Status: ✅ Working
   Purpose: Exchange auth code for JWT access token
   Protection: Client secret validation (server-to-server)
   Response: JSON {access_token, token_type, expires_in, scope}

3. GET /oauth/userinfo
   Status: ✅ Working
   Purpose: Retrieve user profile from PostgreSQL
   Protection: JWT Bearer token validation
   Response: JSON {sub, email, username, name, ...}

4. GET /.well-known/openid-configuration
   Status: ✅ Working
   Purpose: OpenID Connect metadata discovery
   Response: JSON with endpoint URLs and capabilities

5. GET /.well-known/oauth-authorization-server
   Status: ✅ Working
   Purpose: OAuth 2.0 metadata discovery
   Response: JSON with server capabilities

================================================================================
SECURITY FEATURES IMPLEMENTED
================================================================================

✅ Authorization Code Security
   - Cryptographically random (32 characters)
   - Single-use only (deleted after exchange)
   - 10-minute expiration
   - Redis ephemeral storage (not persisted)
   - Client validation before generation

✅ Token Security
   - JWT with HMAC-SHA256 signature
   - 1-hour expiration
   - Claims include: sub, email, username, name
   - No sensitive data in token
   - Bearer authentication in Authorization header

✅ Transport Security
   - Client authentication required for /token endpoint
   - Redirect URI validation (prevents injection)
   - State parameter support (CSRF protection)
   - HTTPS ready (configured in production)

⚠️ Future Enhancements (Phase 2)
   - Token refresh support
   - PKCE for mobile/browser flows
   - Logout/token revocation endpoint
   - Advanced rate limiting
   - Account linking

================================================================================
ARCHITECTURE IMPROVEMENTS
================================================================================

BEFORE (Direct RocketChat API):
  ❌ Tight coupling to Rocket.Chat API
  ❌ Manual user sync required between systems
  ❌ No standards compliance (non-OAuth)
  ❌ Difficult to debug and troubleshoot
  ❌ Hard to scale beyond single client
  ❌ Security concerns with shared credentials

AFTER (OAuth 2.0 SSO):
  ✅ Decoupled architecture
  ✅ Automatic user provisioning
  ✅ Industry-standard OAuth 2.0 + OpenID Connect
  ✅ Easy to trace with standard OAuth tools
  ✅ Supports unlimited OAuth clients
  ✅ Enterprise-grade security (JWT, HMAC-SHA256)
  ✅ PostgreSQL as single source of truth
  ✅ MongoDB independent (no sync needed)

4. Paste into form fields:
   - Authorize URL: https://mediqzy.com/oauth/authorize
   - Access Token URL: https://mediqzy.com/oauth/token
   - Identity URL: https://mediqzy.com/oauth/userinfo
   - Client ID: rocketchat-client-id
   - Client Secret: rocketchat-client-secret-secure-key
   - Scope: openid email profile
   - Username Field: username
   - Email Field: email
   - Name Field: name
   - ID Field: sub

5. Click [Test OAuth] to verify

6. Click [Save Changes]

7. Logout and login with "Login with Mediqzy" button

SUPPORT & TROUBLESHOOTING
================================================================================

Common Issues:

1. "Login button not appearing"
   → Check: Is ENABLED toggle ON in Rocket.Chat OAuth settings?
   → Solution: Enable and save, then refresh page

2. "Invalid client_id error"
   → Check: /home/ubuntu/Mediczy/.env for correct client_id
   → Solution: Restart backend after .env changes

3. "Redirect URI mismatch"
   → Check: ROCKETCHAT_OAUTH_REDIRECT_URI in .env
   → Solution: Must match exactly with Rocket.Chat settings

4. "OAuth endpoints not responding"
   → Check: Is Mediqzy backend running? (pm2 list)
   → Check: Are routes registered? (grep oauth /server/app.js)
   → Check: Backend logs (/logs/server-out.log)
